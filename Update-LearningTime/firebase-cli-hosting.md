# Firebase CLI and Hosting — How It Works

## What is Firebase CLI?

Firebase CLI (Command-Line Interface) is a tool that allows developers to manage Firebase projects directly from the terminal.

For the **Every Week a Winner** project, I used Firebase CLI to authenticate with Firebase, verify the project configuration, and test our frontend locally using the Firebase Hosting Emulator.

## Section 1 — Installing Firebase CLI

Firebase CLI is installed using Node Package Manager (npm).

```powershell
npm install -g firebase-tools
```

### Explanation

- `npm` — Node Package Manager.
- `install` — Installs the specified package.
- `-g` — Installs the package globally.
- `firebase-tools` — The official Firebase CLI package.

### Issue Encountered

During the initial installation, I encountered:

```text
ENOSPC: no space left on device
```

This indicated that the installation could not write the required files because of insufficient disk space.

After addressing the storage issue, I successfully installed Firebase CLI.

### Verification

```powershell
firebase --version
```

Output:

```text
15.33.0
```

This confirmed that Firebase CLI was installed and accessible from the terminal.

## Section 2 — Firebase Authentication

Before managing Firebase resources, developers must authenticate with their Firebase account.

```powershell
firebase login
```

### How It Works

1. Firebase CLI starts the authentication process.
2. A browser window opens for Google account authentication.
3. The developer selects an authorized Google account.
4. Firebase CLI receives authorization after successful login.

The browser displayed:

```text
Firebase CLI Login Successful
```

This confirmed that the CLI was authenticated.

## Section 3 — Firebase Project Configuration

**File:** `.firebaserc`

The `.firebaserc` file identifies the Firebase project associated with the local repository.

Example structure:

```json
{
  "projects": {
    "default": "YOUR_FIREBASE_PROJECT_ID"
  }
}
```

### Explanation

- `projects` — Contains Firebase project aliases.
- `default` — Specifies the default Firebase project.
- The project ID connects local Firebase CLI operations to the intended Firebase project.

To inspect the configuration:

```powershell
Get-Content .firebaserc
```

To list accessible Firebase projects:

```powershell
firebase projects:list
```

## Section 4 — Firebase Hosting Emulator

Firebase Hosting Emulator allows developers to test hosted frontend files locally before deployment.

### Start the Emulator

```powershell
firebase emulators:start --only hosting
```

### Explanation

- `firebase` — Runs Firebase CLI.
- `emulators:start` — Starts local Firebase emulators.
- `--only hosting` — Starts only the Hosting Emulator.

The emulator started successfully at:

```text
http://127.0.0.1:5000
```

### Testing the Frontend

I opened:

```text
http://127.0.0.1:5000/pages/index.html
```

Initially, the root URL displayed a 404 page because the expected file was not available at that route.

Opening the page through `/pages/index.html` successfully loaded the Firebase Hosting setup page.

This demonstrated the importance of understanding the configured public directory and URL paths.

After starting the Hosting Emulator, I opened Chrome Developer Tools and selected the Console tab.

The console displayed:


This message was generated by the Firebase initialization script in:

`frontend/js/app.js`

### What This Confirms

- The frontend loaded the Firebase SDK.
- The Firebase configuration script executed.

## Section 6 — Common Issues and Troubleshooting

### Issue 1 — Insufficient Disk Space

**Error:**

```text
ENOSPC: no space left on device
```

**Solution:** Free sufficient disk space before retrying the npm installation.

### Issue 2 — Page Not Found

**Error:** Firebase Hosting displayed a 404 page at the root URL.

**Solution:** Open the correct frontend page path and verify the `public` directory in `firebase.json`.

### Issue 3 — Missing Favicon

**Error:**

```text
Failed to load resource: 404 (Not Found)
/favicon.ico
```

**Explanation:** The browser requested a favicon that was not present.

This warning did not prevent Firebase initialization.

### Issue 4 — Emulator Shutdown

The Hosting Emulator can be stopped using:

```text
Ctrl + C
```

This shuts down the local emulator process without deleting the Firebase project.

## Section 7 — Development Workflow

The Firebase CLI setup supported the following development workflow:

1. Configure the Firebase project.
2. Authenticate using Firebase CLI.
3. Start the local Hosting Emulator.
4. Open the frontend application.
5. Inspect the browser console.
6. Verify Firebase initialization.
7. Commit tested changes to a feature branch.
8. Submit a pull request for team review.
